## 0. 구조: 단일 소스 원칙

```
spec/characters.json ──┐   (아이덴티티 · 스케일 락)
spec/timeline.json   ──┼──▶ animatic/audio.py  ──▶ renders/odd_haus_score.wav
reference/*.webp     ──┘   animatic/render.py ──▶ renders/odd_haus_animatic_50s.mp4         (클린 컷, 1080p)
                                               └▶ renders/odd_haus_animatic_50s_review.mp4  (리뷰 컷, 720p, 씬/타임코드/연출 노트)
                           docs/03_production_prompts.md ──▶ 본 제작(3D 또는 AI 비디오) 샷 생성
```

- **`spec/timeline.json` 하나가 모든 타이밍의 원본**이다. 씬과 샷, 카메라, 조명, 캐릭터 배치, 애니메이션 포인트, 사운드 큐가 모두 여기 있다. 문서의 표도 이 파일에서 생성했다.
- 타이밍을 바꾸려면 JSON을 고치고 `./animatic/build.sh`를 다시 실행한다. 애니매틱 영상과 사운드가 함께 갱신된다.
- `spec/characters.json`은 캐릭터 룩 락(look_lock), 금지 사항(never), 스케일 값을 담는다. 이미지/비디오 프롬프트(03 문서)의 캐릭터 블록이 이 파일에서 나온다.

### timeline.json 스키마 요약

| 경로 | 내용 |
|---|---|
| `meta` | 길이 50s, 24fps, 1920×1080, 액티브 영역 2:1(레터박스), 카피 |
| `grades.<name>` | 컬러 그레이드 프리셋: exposure, saturation, contrast, shadow_tint, highlight_gain, lift, vignette |
| `scenes[]` | `id, start, end, title_en/ko, emotion_ko, set_ko, lighting_ko, camera_ko, characters[], shots[]` |
| `scenes[].characters[]` | `id`(characters.json 참조), `placement`(화면 배치), `anim[]`(타임코드 포함 애니메이션 포인트) |
| `scenes[].shots[]` | `id, start, end, action_ko, camera, note_ko, animatic{}` |
| `shots[].animatic` | `src`(poster/board), `cam`: `[t, cx, cy, w]` 키프레임(원본 px), `grade`: `[t, preset]`, `fx[]`, `in`(cut/dissolve/flash) |
| `supers[]` | 카피·로고 오버레이(시간, 페이드, 위치, 폰트) |
| `audio` | `beds[]`(룸톤·비·시계·크래클), `music[]`(파트별 구간), `sfx[]`(효과음 큐) |
| `cleanup[]` | 레퍼런스 보드에 박힌 타이틀 글자를 지우는 인페인트 박스 |

### 애니매틱 FX 어휘 (`animatic.fx[].type`)

| type | 용도 | 주요 파라미터 |
|---|---|---|
| `fade` | 페이드 인/아웃, 밝기 램프 | `t0, t1, from, to` |
| `glow` | 램프, 문틈 빛, 태그 반짝임(스크린 블렌드) | `at`(원본 px), `radius`, `color`, `strength`(숫자 또는 키프레임), `pulse` |
| `blink` | A.A. 저전력 빨간불 | `at, radius, color, t0, t1, hz` |
| `shadow` | Mr. ODD의 그림자가 화면을 훑고 지나감 | `t0, t1, from, to`(화면 정규화 좌표), `size, strength` |
| `shake` | 발소리, THUD 충격 | `t, amp`(원본 px), `decay` |
| `punch` | 비트에 맞춘 순간 줌(귀 쫑긋, 리프) | `t, amount, dur` |
| `door` | 세로 슬릿 빛이 화면 전체로 열리는 리빌 | `t0, t1, center` |
| `sparkle` | 꼬마전구 트윙클(밝은 웜 포인트 자동 검출) | `region, count, size, t0, t1` |
| `scrim` | 카피 가독성용 국소 암부 | `t0, t1, center, radius, strength` |
| `flash` | 웜 화이트 플래시 | `t, dur, strength` |
| `blur` | 엔드 카드 배경 보케 | `t0, t1, from, to` |

## 1. 캐릭터 스케일 시트

> **기준 단위 1.0 = 작은 친구 기준키 14cm.** 모든 샷에서 이 비율을 지킨다. 원근으로 과장하는 것은 괜찮지만, 같은 평면에 섰을 때의 비율은 바뀌면 안 된다.

| 캐릭터 | 실제 기준 | 상대 크기 | 한눈에 보는 기준 |
|---|---|---|---|
| Picker | 11cm | ×0.8 | 가장 작다 |
| Vin | 지름 12cm | ×0.85 | |
| A.A. | 13cm (비니 포함) | ×0.95 | |
| Locke | 14cm (모자 포함) | ×1.0 | **기준** |
| Rex | 18cm (왕관 포함) | ×1.3 | 작은 친구 중 가장 크다. 그래도 Buddy 앞다리 길이를 넘지 않는다 |
| **Buddy** | 어깨 38cm / 머리 끝 48cm | **×3.5** | 작은 친구 키 ≈ Buddy 앞발(발목 아래) 높이 |
| **Bully** | 142cm | **×10** | Buddy 머리 끝 ≈ Bully 무릎. 작은 친구 키 ≈ Bully의 **스니커즈 높이** |
| **Mr. ODD** | 198cm, 어깨 폭 70cm | **×14** | Bully 머리 ≈ Mr. ODD 가슴. 작은 친구 키 ≈ Mr. ODD의 **머그잔 높이** |

**체인 규칙** — 작은 친구 → Buddy 발목 → Bully 무릎 → Mr. ODD 가슴.

### 스케일 QC 체크리스트 (모든 샷)
- [ ] Bully와 작은 친구가 함께 나오면, 작은 친구 키가 Bully 신발 높이를 넘지 않는다.
- [ ] Buddy와 작은 친구가 함께 나오면, Buddy 머리가 작은 친구의 3배 이상 높다.
- [ ] Bully의 **뒤로 쓴 모자**가 실루엣으로 읽힌다(S04 전 샷, S06 · S07).
- [ ] Buddy는 네 발, 개 해부학을 유지한다. 'BUDDY' 태그와 줄무늬 넥타이를 착용한다.
- [ ] Mr. ODD는 머그잔(집 아이콘)을 들고 있다. 악역 표정(이빨을 드러낸 으르렁)은 쓰지 않는다.

## 6. 애니매틱 렌더

```bash
./animatic/build.sh            # 폰트 다운로드 → 사운드 합성 → 클린/리뷰 컷 렌더
# 개별 실행
./animatic/fetch_fonts.sh      # OFL 폰트(Cormorant Garamond, Patrick Hand SC, Nanum Myeongjo, NanumGothic)
python3 animatic/audio.py      # renders/odd_haus_score.wav
python3 animatic/render.py     # renders/*.mp4 (CPU 코어 수만큼 병렬)
python3 animatic/render.py --stills 5,22.1,35.95,38.9,47 --scale 0.5   # 특정 시점 스틸만 빠르게
```

- 의존성: Python 3.10+, `numpy`, `Pillow`, `fonttools`, `ffmpeg`(libx264, aac), 폰트 다운로드용 `npm`과 `pip`.
- 애니매틱은 두 장의 레퍼런스 이미지(키 비주얼 포스터, 스토리보드 보드)를 가상 카메라로 크롭·이동하고 그레이드와 FX를 얹어 만든다. **본 제작 영상이 아니라 타이밍·감정선·사운드 싱크를 검증하는 프리비즈**다. 레퍼런스에 없는 동작(Locke가 문을 여는 손동작 등)은 빛·카메라·사운드로 대신 표현하고, 리뷰 컷 하단 노트로 의도를 설명한다.
- 이미지 처리는 내부 해상도(출력의 2/3)에서 하고 마지막에 업스케일한다. 카피와 로고는 출력 해상도에서 선명하게 합성한다.

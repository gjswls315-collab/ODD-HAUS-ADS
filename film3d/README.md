# ODD HAUS — 3D brand film (real-time Three.js production)

Everything you see is **real 3D geometry rendered live**: eight procedurally modelled, rigged
characters inside a modelled ODD HAUS interior, filmed by a moving virtual camera with depth of
field, shadows, bloom and grain. No storyboard images, cutouts or background plates are used
anywhere. The reference images in `../reference/` were used only to understand mood, scale and
character design.

## Review build 2 (current): rebuilt characters + planted-foot walking

Feedback on build 1: the walking looked wrong and the 3D models looked cheap. Both were rebuilt
at the root:

**Modelling.** Bully, Mr. ODD and Buddy are now sculpted, single-surface, skinned meshes
(`assets/chr_*.glb`) generated by code in `tools/model/`. Each body is a signed-distance sculpt
(smooth unions of round cones, ellipsoids, tori and hair/fur locks), meshed with marching cubes,
decimated in Blender (run as a Python module), painted with vertex colour + baked ambient
occlusion, and skinned to a real armature (spine, neck, head, clavicles, arms, 3-joint fingers,
legs, toes; Buddy: spine, neck, head, jaw, ears, 4-segment tail, three-segment legs, tie, tag).
No mannequin capsules or ball joints are left on any character.

- Bully: big kid head, rosy cheeks, gap-toothed grin, messy blond locks under a backward black
  snapback, black skull tee (print decal), studded wristband, baggy olive cargo pants, high-tops.
- Mr. ODD: wide jowly face, walrus moustache, heavy brows, curly hair going grey, plaid robe with
  shawl collar over a white shirt, rope belt with tassels, striped pyjama trousers, sheepskin slippers.
- Buddy: shaggy terrier mix; fur built from ~1,500 layered clumps that flow over the body
  (back -> flanks, beard, chest ruff, ear and tail plumes), white shirt collar, striped tie, BUDDY tag.
- Small friends: continuous rubber-hose limbs (one smooth tube per limb, rebuilt every frame),
  sculpted cartoon gloves with pivoting fingers and chunky high-top sneakers (`assets/kit_tiny.glb`).

**Walking.** Feet are planted. `src/characters/gait.js` gives each foot a stance phase (fixed
on the floor while the body passes over it, rolling heel -> flat -> toe) and a swing phase
(arcing to the next footprint), all as a pure function of distance travelled, so feet never
skate. Legs reach their footprints with two-bone IK (`src/characters/pose.js`, works on any
bone orientation); pelvis height comes from what the legs can reach, which creates the natural
up-on-passing / down-on-contact rhythm, plus hip sway, hip yaw/roll, counter-swinging arms
and head stabilisation. Buddy uses the same idea on four paws (lateral-sequence walk, diagonal
trot) with body height and pitch from the front/hind pairs (`src/characters/dogrig.js`).

## Run it

```bash
npm install            # three (+ playwright for headless renders)
npm run serve          # http://localhost:8080  (three.js loads from the jsDelivr CDN)
```

URL parameters: `mode=lineup|free|shot|reel`, `shot=A|B|C|W|V`, `debug=1` (or `#A`, `#W`, `#free`, `#debug` ...).

Keys: `SPACE` play/pause · `R` restart · `1` lineup · `2` `3` `4` shots A–C · `5` reel · `6` free camera ·
`←/→` scrub ±1 s · `L` labels (lineup) · free camera: drag/right-drag/scroll, `WASD` + `QE`, `Shift` faster.

`?debug=1` shows film time, scene, shot, camera position/FOV, depth-of-field, which assets are GLB vs
procedural, FPS, draw calls and triangles.

## Headless renders

```bash
node tools/capture.mjs video  --query "mode=shot&shot=A" --w 1280 --h 720 --fps 24 --out renders/review1/shot_A.mp4
node tools/capture.mjs stills --query "mode=lineup" --times 0.5 --out renders/review1 --prefix lineup \
     --cams '[{"pos":[-0.85,1.05,1.0],"target":[-0.9,0.72,-2.65],"fov":38}]'
```

Every animation is a pure function of time, so any frame renders identically in any order.
Capture runs Chromium + SwiftShader (no GPU needed) and serves the CDN imports from `node_modules`.

## Architecture

```
src/
  core/      util (easing, noise, paths) · textures (all canvas-painted) · mats · geo (eyes, gloves,
             hands, sneakers, fur/hair clumps, contact shadows) · stage (renderer + DoF/bloom/grade)
  characters/
    base.js     CharacterRoot / VisualModel / AnimationController, GLB-first loader
    pose.js     rest-orientation-agnostic posing (character-axis rotations) + two-bone IK
    gait.js     planted-foot biped locomotion (stance/swing, heel-toe roll, pelvis from reach)
    humanrig.js controller for the skinned Bully / Mr. ODD rigs (gait, arms, fingers, IK, face)
    dogrig.js   controller for the skinned Buddy rig (four planted paws, walk/trot, ears, tail)
    glb.js      GLB preparation: materials by name, eyes on sockets, props on bones
    tinykit.js  sculpted gloves/sneakers + rubber-hose limbs for the small characters
    tinyrig.js  shared biped for the object characters + TinyRigController
    tiny.js     Vin, Picker, A.A., Locke, Rex
    buddy.js    Buddy + DogController (4-leg walk/trot, sniff, ear perk/down, tail wag, lie down)
    human.js    human skeleton + HumanController (walk, crouch IK, look, gestures, 2-bone arm IK)
    bully.js    Bully (+ red flying-V)       mrodd.js  Mr. ODD (+ mug)
  world/house.js  the ODD HAUS interior + night lighting rig
  film/shots.js   lineup, free-camera staging, test shots A/B/C, walk tests W/V
tools/model/      character sculpting + rigging (Python: numpy, scikit-image, Blender bpy)
  sdf.py  rigkit.py  charkit.py  hands.py  chr_bully.py  chr_mrodd.py  chr_buddy.py  kit_tiny.py  build.py
```

Film logic never touches geometry: shots only write a `CharacterState`
(`pos, yaw, dist, moving, run, look, freeze, crouch, custom{…}`) and the character's
`AnimationController` turns that into joint transforms on named rig nodes.

## Replacing a procedural character with a final GLB

Drop `assets/chr_<id>.glb` (ids: `vin picker aa locke rex buddy bully mrodd`). On load each character
tries the GLB first and falls back to the procedural model, so no scene code changes. The GLB is
scaled to the character's height automatically. Name the rig nodes like this so the existing
controllers drive them:

| Rig node | Used for |
|---|---|
| `AnimationPivot` | root bob / lean / sway |
| `Body` | hips (humans) or main body (objects, dog) |
| `Spine`, `Chest`, `Neck`, `Head` | torso + look-at (humans, dog uses `Neck`/`Head`) |
| `EyeL`, `EyeR` | optional; procedural eyes expose look + lids |
| `LeftArm`, `LeftForeArm`, `LeftHand` (+ Right…) | arm swing, gestures, IK |
| `LeftLeg`, `LeftShin`, `LeftFoot` (+ Right…) | walk cycle, crouch |
| Dog: `LegFL/FR/HL/HR` (+`…Lower`, `…Paw`), `EarL/R`, `Tail`, `Tail1-3`, `Tie`, `Tag` | quadruped gait + secondary motion |

Missing nodes are simply skipped (root motion still works).

# 01. 기존 코드 분석과 시각 문제 보고 (리팩터링 전)

분석 대상: `eclipse-requiem/game` (커밋 5ebe7ce 기준). 아래 내용은 소스를 직접 읽고 grep으로 센 값과 실제 실행 캡처로 확인한 것만 적었다.

## 1. 구조

| 항목 | 확인 내용 |
|---|---|
| 언어 · 빌드 | TypeScript 5.6 + Vite 5. 외부 게임 엔진 없음. `npm run build` → `release/eclipse-requiem.html` 단일 파일 |
| 렌더링 엔진 | 자체 Canvas 2D 렌더러 `src/gfx/renderer.ts`. ① 640×360 월드 캔버스 → 화면에 nearest 확대, ② 화면 해상도 캔버스에 가산 합성 글로우 패스, ③ 같은 캔버스에 1920×1080 설계 좌표 UI |

## 2. 그래픽이 실제로 그려지는 방식

### 2-1. 이미지 에셋: 없음
- 프로젝트 안에 PNG·JPG·WebP 파일 0개. 소스에 `new Image`, `fetch(`, `.png` 참조 0건.
- 부팅 시 `buildArt()`(`src/gfx/sprites.ts:47`)가 모든 스프라이트를 **코드로 생성**한다.
  `pix.ts`의 `sprite(w, h, draw, palette)`가 캔버스 경로(ellipse·quadraticCurveTo·fillRect)로 벡터 도형을 그린 뒤 팔레트 양자화 + 1px 외곽선을 입힌다.
- 결과: 그래픽 수정 = 코드 수정. 아티스트가 그림 파일을 교체할 방법이 없다.

| 요소 | 현재 구현 (코드 위치) | 문제 |
|---|---|---|
| 플레이어 | `art/heroines.ts` 절차 생성 40×34, 프레임 **3장**(날개 −1/0/1). 피격은 흰 실루엣 | 상하 기울기·피격 자세·폭탄 시전 프레임 없음 |

| 폭탄 | `world.ts:304-368` `fillRect`·`arc`·`lineTo`로 직접 그림 | 이펙트 에셋 없음 |

## 3. 시각 문제와 원인 요약

| # | 문제 | 원인 |
|---|---|---|
| 1 | 그래픽이 코드에 묶여 있어 교체·개선이 불가능 | 이미지 에셋 파이프라인 자체가 없음 |
| 2 | 도형으로 그린 샷·오라·폭탄·폭발·위험 요소 | 이펙트를 스프라이트 애니메이션이 아니라 그리기 명령으로 구현 |
| 3 | 픽셀 격자 붕괴 | 탄·종·유령 얼굴의 런타임 회전, 일러스트의 ×5·×2.5 확대와 회전 |
| 4 | 화면 전체가 번지고 보라·적색으로 물듦 | 모든 탄·샷·적·조명에 가산 글로우, 보라 적탄, 붉은 틴트 |
| 5 | 캐릭터가 움직임 없이 미끄러짐 | 비행 3프레임, 기울기·피격·시전 프레임 없음 |
| 6 | 배경이 평평하고 장식적 | 그라데이션·다각형 배경, 켜진 창문과 가로등, 명도 규칙 없음 |
| 7 | 보스가 화면을 덮음 | 부품 크기 합이 화면 높이 약 74% |
| 8 | UI가 게임과 다른 미술 언어 | 고해상 벡터 글꼴 + 금 테두리 패널 |

캡처: `captures/before/` (1280×720, `scripts/capture.mjs`로 같은 시점 재현 가능).

## 4. 리팩터링 방침

새로 만들지 않고 현재 프로젝트의 렌더링 구조를 바꾼다.

1. 그래픽은 `game/assets/`의 PNG + JSON(Aseprite 내보내기 형식)으로 분리하고, 게임 코드는 그것을 불러 그리기만 한다.
2. 부팅 시 그래픽 생성 코드(`src/gfx/art/*`, `pix.ts`, `sprites.ts`의 buildArt)를 런타임에서 제거한다.
3. 현재 내가 이미지 생성 도구를 쓸 수 없으므로, **임시 에셋**은 `tools/art/`의 오프라인 스크립트로 픽셀을 직접 찍어 PNG로 만든다. 이 파일들은 규격을 지키는 자리 표시용이며 최종 아트가 아니다. 같은 규격의 PNG·JSON으로 덮어쓰면 그대로 교체된다.
4. 게임 시스템(선택·이동·발사·차지·폭탄·탄막·파워업·진행·페이즈·게임오버·재시작)은 건드리지 않고, 변경 전후로 같은 자동 테스트를 돌린다.
